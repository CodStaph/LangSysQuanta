## 2. 实现（`bootstrap/src/names_stage.ls`，全部内联）

### 2.1 显式方法调用（解析侧）

`.` 分支内、`svi >= 0` 之后新增方法调用识别：

- 条件：`sidx < 70`（普通 struct）且紧跟 `(`，方法名字节比对 `eq`(101,113) / `lt`(108,116)。
- 映射：`eq → tc=2 (Eq)`、`lt → tc=1 (Ord)`；扫 impl 表 `(tc, 30+sidx)` 行，
  无行 → `E-LS-NO-IMPL: trait method call has no impl for this type`。
- 语义：接收者先压 kind 89（地址、类型 `30+sidx`）；实参限定为**同类型 struct 裸变量**
  （`name_id + sv_find`，类型必须等于接收者，否则
  `E-LS-UNSUPPORTED: trait method argument must be (a struct variable of) the same struct type`）。
- 结果：kind 93 节点、`post[100000+mi] = 0`（meta 0 = 无运算符派生/取反，纯
  `pop rsi; pop rdi; call; push rax`），结果类型 Int。**零新增发射代码**。

### 2.2 `Add` impl 与 `+` 派发

- 注册：impl 头 trait 名识别新增 `Add`（65,100,100）→ `tc=4`；目标规则
  `(tc ∈ {1,2,4,5}) && ty ≥ 30`（Add 只能落在用户 struct 上；`impl Add for Int` 拒绝）。
- 派发：`push_binop` struct 路径新增分支——`op == 1 && t1 == t2 ∈ [30,100)`：
  扫 impl 行 `(4, t1)`，无行 → `E-LS-NO-IMPL: struct addition has no impl of Add for this type`；
  有行 → kind 93、meta 1（同样无派生/取反），结果 Int（文档约束：Add impl 方法必须返回 Int）。

### 2.3 预扫描修复（文本级 arity 检查）

`p.eq(q)` 中标识符 `eq` 是注册的 impl 方法函数（2 参），文本级 arity 预扫描把它当作
直接调用（逗号数 1 ≠ 2）→ 误报 `E-LS-ARITY`。修复：预扫描遇到**`.` 前导**的标识符
（成员调用）直接 `continue`，不做参数计数。

> 注：显式方法调用的实参解析初版用 `parse_index` 递归，在 if 条件上下文中
> 参数解析异常失败（现象为条件解析报 `ctl: bad if expr`，根因未完全定位）；
> 因 C 的语义本就把实参限定为裸 struct 变量，改为直接 `name_id + sv_find` 后行为正确且诊断更精确。
> 该 `parse_index` 嵌套上下文问题记为已知未解疑点（不影响既有用例）。
