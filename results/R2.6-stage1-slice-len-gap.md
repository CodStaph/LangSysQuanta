## 1. 背景与根因

| 路径 | 命令 | 结果 |
|---|---|---|
| B-LS 解释器（seed.c） | `seed --run <test.ls>` | 完整支持 `.len`（Str 字面量/变量、Slice 变量/ref、struct 字段） |
| stage1 编译器（names_stage.ls） | `seed --run names_stage.ls <test.ls>` | 只支持部分 `.len` |

`names_stage.ls` 的 parse_expr `.` 成员访问分支（2888 起）只覆盖：
`var_find`（ref Str/Slice）、`str_find`（普通 Str 变量）、`sv_find`（struct）。
**缺失：普通 Slice 变量（sl_find 表）、字符串字面量。**

- `slice_params.ls`：`if s.len != 2`（s 为普通 `Slice[U8]`）→ 缺 `sl_find` 分支。
- `unicode.ls`：`if "你好".len != 2`（字符串字面量）→ parse_expr 根本不支持字符串字面量。

两者均与 R2.6-A 无关（原始版本同样失败）；官方 CI（run-interp.sh）走解释器路径，实测全 PASS。

## 2. 缺口1 修复（已完成）

在 parse_expr `.` 分支（2914 `else`）的 `str_find` 之后补 `sl_find` 分支：

```ls
} else if (sl_find(post, name, st[4]) >= 0) {
    // 普通 Slice 变量 .len：Slice 值 = 16 字节帧槽 [off]=base,[off+8]=len。
    // 复用 kind 12（mov rax,[rip+val]）读 off+8 的长度字；仅接受 "len" 拼写。
    ...
    push_post(post, st, 12, off+8); set_ty(post, st, 1); expect = 0;
}
```

零新增顶层函数（128/128 触顶）。

### 验证（stage1 编译路径）

- `slice_params.ls`：rc=4 → **rc=0**（普通 Slice `.len` 通过）
- 31 项泛型/struct/trait/ref/slice 回归：**0 失败**
- Str `.len`、ref Slice `.len`、struct 字段：未破坏（str/slice_at/ref_str_slice 全 rc=0）

## 3. 缺口2（未完成，范围扩大）

`unicode.ls` 需要 `if "你好".len != 2`。实测：
- `if x == "hello"`（if 条件里字符串字面量）→ `ctl: bad if expr`（**parse_expr 不支持字符串字面量**）
- `let n = "hello".len` → `str: expected ;`（let 字面量分支不接 `.len`）

即缺口2 的根因是 **parse_expr 无字符串字面量支持**，比"补 .len 分支"大得多（涉及字面量解析、Str 常量存储、表达式集成）。非 CI 必需（unicode 在 run-interp 走解释器路径）。
