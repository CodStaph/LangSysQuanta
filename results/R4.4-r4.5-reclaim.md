> 状态：**完成（2026-10-23）**。QEMU 固定点 `37f525be…84d1`，`stage2 == stage3`，`QEMU-GUEST: RESULT=PASS`。
> 上位：[`MEMORY.md`](../MEMORY.md) §R4、[`results/R4.2-r4.4-arena.md`](R4.2-r4.4-arena.md)、
> [`results/R4.3-str-failure.md`](R4.3-str-failure.md)。
> 范围：R4.4 的**显式 mark/rewind 段回收**（bump arena 下唯一可靠的“非栈顶回收”形式）与
> R4.5 的**分配失败注入回归**；按 region 硬配额、通用 `free`/碎片整理仍在边界之外。

## 1. R4.4 收尾：`arena_mark()` / `arena_rewind(m)`

| 内置 | 语义 |
|---|---|
| `arena_mark() -> Int` | 返回 `current - base`（回退令牌） |
| `arena_rewind(m) -> Int` | 成功退回 `m` 字节并返回 `0`；否则 `-1` |

- 成功条件：`0 <= m <= used`，且**不能在最内层 region mark 之下**（否则 region 退出会“向前跳”到
  陈旧 mark，破坏 region 记账）；
- 成功时 `current = base + m`、`reclaims += 1`；`high_water` 保留峰值；
- 语义：回退会同时释放 `m` 之上的**所有**分配（多分配段回收），因此比 `b.release()`/`drop`
  （单块、LIFO、owner 匹配）更通用；被回退的 Buffer/Str 句柄立即失效，调用方负责不再使用；
- 与 region 的关系：`region` 退出本身等价于“回退到进入时的 mark”，`arena_rewind(mark)` 在
  退出前手动做同一件事是合法的（幂等）。

实现：

- `builtin_code` 20/21；post kind 67（读 `current-base`）与 kind 68（校验 + 回退 + 计 `reclaims`）；
- kind 68 的 region 守卫：`depth > 0` 时比较 `base+m` 与 `mark[depth-1]`，`jb` 即失败。

## 2. R4.5：失败路径回归 + `?` 传播

新增 `stage1_alloc_fail.ls`（退出码 7）覆盖：

1. `?` 的 **Ok 路径**：`fn cat(a,b) -> Result[Str, AllocError] { let s: Str = str_try_concat(a,b)?; return Result.Ok(s); }`；
   `fn get_buf(cap) -> Result[Buffer[Int], AllocError]` 内部 `let b: Buffer[Int] = r?;`（Buffer 句柄经 `?` 解包）；
2. 填满 arena（`arena_budget() - arena_used()`）后：`cat`/`get_buf` 经 `?` 传播 `Err(-1)`，
   `arena_used()` 不变；
3. `arena_alloc(budget+1)` → `-1`；`arena_stat(2)`（rejects）精确为 3（Str / Buffer / arena_alloc）；
4. `concat_into` 目标容量不足 → `Err`，且输出 `out[0]` 未被部分写入；
5. `arena_reset()` 之后同样的操作重新成功（恢复路径）。

配套的**语言侧修正**（R4.5 需要）：

- `parse_index` 的变量分支改用**变量真实类型**（原来一律记为 Int）——否则 `Result.Ok(b)` 的
  Buffer 载荷（type 9）会报 `ctor: payload type mismatch`；
- `Result`/`Option` 变量现在可以作为表达式出现（新增 post kind 69：读 opt 表的块指针），
  因此 `let b: Buffer[Int] = r?;` 可用（此前 `?` 只接受内联调用）。

## 4. 行为/固定点

- 同源编译行为：120 个输入里 **118 个 `rc`/stdout/stderr 一致**，2 个预期差异是新测试
  （旧编译器不认识 `arena_mark`/`arena_rewind`/`Result` 变量 `?`）；
- `names_stage` 自编译：`9d03f030…583b` 575457 B → **`37f525be…84d1` 589334 B**；
- QEMU 固定点 **`37f525be…84d1`**；
- 注意：输出缓冲 `out` 为 610000，而本版最大输出 589334，余量约 **20 KB**；下一轮改编译器源码
  前应先把 `out`/`code` 扩一点（现在宿主解释器已放宽到 16 MiB，扩容不再受 4 MiB 限制）。

## 5. 边界

| 项 | 状态 |
|---|---|
| `arena_mark` / `arena_rewind`（多分配段 LIFO 回收） | ✅ |
| rewind 的 region 守卫（不越过最内层 mark） | ✅ |
| 回收计数（release/drop/region/reset/rewind） | ✅ |
| 分配失败回归（Str/Buffer/arena_alloc/concat_into） | ✅ R4.5 |
| `?` 传播 AllocError（含 Buffer 载荷、Result 变量） | ✅ |
| 通用 `free`（任意顺序释放、空洞复用） | ❌ bump arena 不支持；需要空闲链表/分代分配器 |
| 碎片整理 / 压缩 | ❌ 同上（bump arena 无碎片概念） |
| 按 region 的**硬配额**（超出即失败） | ❌ 无 surface 语法；需要把配额槽接进所有分配点（含 flat helper），留待设计 |
| 分 region 峰值 | ❌ 只有全局 `high_water` |
| 回退后句柄失效检测 | ❌ 运行时/静态均不检查（调用方负责） |

**后续建议**：R4 的可行部分已收口（R4.2/R4.3/R4.4-可做项/R4.5）。剩余项都需要新的分配器设计
（空闲链表或分代 arena），建议单独立项；语言侧下一项转 **B4 多参数泛型/约束**。
