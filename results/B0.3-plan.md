## 1. 为什么这不是一次「改文件」就能完成的重构

对 `bootstrap/src/names_stage.ls` 的实测（2026-10-22）：

| 事实 | 数值/位置 |
|---|---|
| 语句级 parse+emit 交织的主体循环 | 约 **1,001 行**（`main` 内的 `while 1 { … }`，从 `let have_ret = 0;` 到函数结束前） |
| 循环内 `parse_expr`/`emit_expr`/`emit1`/`emit4`/`emit_ret` 调用 | **168 处**（解析与发射交错） |
| 控制流状态 | 手写控制栈 `ck[64]` + `cd`，补丁数组 `cje/cstart/cjmp/bloop/bpos[64]`，全部是 `main` 的局部量 |
| 表达式侧 | 已有后缀 IR（`post[]` + `push_post`/`set_ty`），**emit 已消费表达式 IR**，不是纯源码扫描 |
| 编译器自身的状态载体 | 只有函数参数 `Slice[U8]`/`Slice[Int]`；**无全局变量、无 struct-with-slice、无 Slice 再切片** |
| 函数参数上限 | 6（`MEMORY` §1.2 已登记） |

要把语句循环改成「AST 驱动」，必须把这段 1,000 行逻辑从 `main` 里挪出来，成为
`emit_body(ctx, …)`；而它需要 `st/cs/ck/cje/cstart/cjmp/bloop/bpos`（8 个 Int 数组）
加 `src/code/data/out`（4 个 U8 数组）——**远超 6 参数**，且 stage1 不能把这些打包进
struct（slice 字段未支持），也不能对已有 `Slice` 再做 `slice()`（`slice()` 只接受 Array）。
因此 B0.3 有一个**语言侧前置条件**（P1），不是单纯的代码搬家。

## 2. 目标形态（AST 布局）

### 2.1 语句 AST（嵌套，扁平存储 + 子表区间）

```text
sast[]，每条记录 6 ints：
  +0 kind（K_LET/K_ASSIGN/K_RETURN/K_EXPR/K_WRITE/K_IF/K_WHILE/K_MATCH/
           K_REGION/K_COMPTIME/K_BREAK/K_CONTINUE/K_BLOCK）
  +1 span_start（源码字节偏移，指向语句首 token）
  +2 span_end（语句结束后的第一个字节，含 `;` 或 `}`）
  +3 depth（嵌套深度，0 = 函数体顶层）
  +4 first_child（子语句记录下标；叶子 = -1）
  +5 child_count
每函数另存 (body_start, body_end, first_stmt, stmt_count)。
```

- 解析阶段只**建表**：`scan_stmts` 逐函数产生语句树（花括号匹配、`;` 终结、`else if` 链、
  `match` 分支、`region`/`comptime` 块），不做任何 emit。
- 表达式节点继续用现有后缀 IR（`post[]`），但在语句记录里存 `expr_start/expr_len`
  （`post` 的区间），这样语句 AST 不复制表达式结构，又能让 emit 只看 AST。

### 2.2 两阶段发射

```text
phase A  parse_stmt_list(fn)   → sast[]（+ 每语句的 post 区间、符号/槽位信息）
phase B  emit_stmt_list(fn)    → 机器码（按 sast 记录逐条 emit，控制流用 AST 下标做标签）
```

控制流降低规则（替代现在的补丁数组）：

| 语句 | phase B 生成 |
|---|---|
| `if c { A } [else if …] [else B]` | 记录 `cond_expr`、`then_child`、`else_child`；emit 时先 `emit_expr(cond)`，再 `jz else_label`，A、`jmp end`、`else_label:`、B、`end_label:` |
| `while c { A }` | `loop_start:`、`emit_expr(cond)`、`jz end`、A、`jmp loop_start`、`end:`；`break`/`continue` 由 AST 里最近的外层循环记录在 emit 时回填 |
| `match e { arm… }` | 现有 tag 比较保留，只是按 AST arm 列表发射 |
| `region { A }` / `comptime { A }` | 直接展开子语句（B-LS 的 `region` 已是词法分组） |
| `let`/assign/return/expr/write | 保持现有 `emit_expr` 调用，参数来自 AST 记录 |

标签用 `2 × sast 下标` 之类稳定编号，不再依赖「当前 64 槽补丁数组」的深度巧合。

## 3. 前置条件（P1，必须先做）

三选一，按成本递增：

1. **给 `Slice` 增加再切片**：内置 `slice_at(s: Slice[T], off: Int, len: Int) -> Slice[T]`
   （seed 解释器 + stage1 codegen + 文档 + 单测）。之后 `emit_body` 只需一个
   `Slice[Int] ctx` + 一个 `Slice[U8] mem` + `n` + `Slice[Int] ps` = 4 参数。
2. **允许 `Array` 作为函数参数**（stage1 + seed 同步），同样能把大数组传进 `emit_body`。
3. **给编译器加 struct-with-slice 字段**（最重，但一次解决后续 B2/B3 的上下文问题）。

推荐 **P1.1**：最小、对语言使用者的语义影响最小（只是切视图），且 B2 的「词法作用域表」
也需要按区间访问数组。

## 5. 风险与回滚

- **风险 R1**：`scan_stmts` 的语句边界与现有解析不一致（`else if`、`match` 分支、
  struct literal 里的 `{`、字符串/注释里的花括号）→ 用 B0.2 已有 body span + 79 输入
  逐字节回归快速定位。
- **风险 R2**：`emit_body` 抽取时状态泄漏（`dlen`、`nf`、`st[6]` 数据段偏移）→ 抽取阶段
  只搬代码、不改赋值，先保证哈希不变，再改结构。
- **风险 R3**：AST 标签/跳转回填与旧补丁数组语义偏差（尤其 `break` 复用）→ 保留
  `break_nested`/`logic_ops` 两个专门用例，并在 QEMU 里跑。
- **回滚**：每个阶段一次独立提交；B0.3a/b/c 任一阶段失败，`git revert` 该提交即回到
  上一可用状态（B0.2 的 `a1b0847`）。

## 6. 与其它 B 线项的关系

- **B2（region + `val`/`ref`）** 需要词法作用域：`sast` 的 `depth` + body span 正好是作用域树；
  B0.3b 抽出的 `emit_body` 之后，B2 可以在 phase A 里插作用域表而不碰 emit。
- **B3（Buffer/arena）** 与 B0.3 独立，可并行；若优先交付语言能力，先做 B3 更划算。
- **B4（多参数泛型）** 依赖参数类型表：B0.2 的 `params_start/end` 已留槽，B0.3c 可一并把
  参数类型解析前移。
