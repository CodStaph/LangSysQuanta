# R4.3 · Str/切片分配的运行时失败（替换 trap）

> 状态：**完成（2026-10-23）**。QEMU 固定点 `4fa74081…9a0b`，`stage2 == stage3`，`QEMU-GUEST: RESULT=PASS`。
> 上位：[`MEMORY.md`](../MEMORY.md) §R4、[`results/B3-buffer.md`](B3-buffer.md)（Buffer 侧失败路径）。
> 范围：把 `Str +` / `concat_into` / `append_into` 的**预算/容量不足**从 `exit(70/71)` 改成
> 可处理失败；不改变成功路径的语义，不做通用 `free`/对齐收口（仍属 R4.2/R4.4）。

## 1. 问题

`bootstrap/helper/genop_str.asm` 是内嵌在 stage1 里的 hand-written flat binary（`genop_str[1085]`，
由 `bootstrap/helper/embed_genop.py` 从 `nasm -f bin` 生成）。旧版在两类失败上直接退出进程：

| 位置 | 条件 | 旧行为 |
|---|---|---|
| `concat`（`Str +`） | `arena_current + bytes > arena_end` | `exit(70)` |
| `slice_concat_into` / `slice_append_into` | `out_len + src_len > out_cap` | `exit(71)` |

后果：预算不足不是可处理错误（没有 `Result`、没有错误码返回），调用方无法降级/记录/重试；
退出码 70/71 与正常返回值混淆；与 `Buffer.try_new → Result[Buffer[Int], AllocError]` 的契约不一致。

## 2. 设计

### 2.1 helper 的失败契约（不再 exit）

结果/输出 box 的 **tag** 承担状态：

| tag | 含义 |
|---|---|
| 3 | `Str` 成功（`+8` ptr、`+16` bytes、`+24` chars） |
| 4 / 5 | `Slice[U8]` / `Slice[Int]` 成功（`+8` base、`+16` len） |
| 9 | **失败**（Err）：`Str` box 载荷清零；`*_into` 输出 box **不写入**、len 保持原值 |

- `concat` 失败：`[rcx]=9`、`[rcx+8..+24]=0`，**不推进** `arena_current`；
- `slice_concat_into`/`slice_append_into` 失败：`[rcx]=9`，返回原 `(base,len)`（全有或全无，无部分写入）；
- 只保留 **类型/标签不匹配** 的 `trap`（`exit(70)`）——那是编译器不变量，正确程序不可达。

### 2.2 surface

| 形式 | 类型 | 失败语义 |
|---|---|---|
| `str_try_concat(a, b)`（新内置，post kind 64） | `Result[Str, AllocError]` | 预算不足 → `Result.Err(-1)`，arena 不变 |
| `concat_into(x, y, out)` | **`Result[Slice[T], AllocError]`**（B3 起是 `Slice[T]`，本次改为可失败） | 目标容量不足 → `Err(-1)`，`out` 不变 |
| `append_into(x, y, out)` | 同上 | 同上 |
| 泛型 `T + T`（`T = Str`/`Slice`） | `T`（语法不变） | **不再 trap**：失败时得到空 `Str`（tag 9 box 解包为零长度） |
| 直接 `Str + Str` / `Slice + Slice` | — | `E-LS-UNSUPPORTED`（旧实现是整数加法，属误编译；改用 `str_try_concat`） |

实现要点：

- 新内置 `str_try_concat`：`builtin_code` 17 → parse 两个 `Str` 实参（`parse_index` + `box_last_arg`）
  → post kind 64。emit 在静态区放 **Str box（32 B）+ Result 块（32 B）**，调用 helper 后按 tag 写
  `Ok(Str)` 或 `Err(-1)`，最后压入 Result 块指针；
- `concat_into`/`append_into`（kind 31）：保留原有三个 box 的构造与调用，调用后检查输出 box 的 tag，
  在静态 Result 块（24 B：tag + base + len）里写 `Ok(base,len)` 或 `Err(-1)`；
  表达式类型改为 `mk_res_ty(ty1, 10)`；
- `?` 可直接用于这两种 `Result`：`Result[Str, AllocError]?` 会 push 3 个字（ptr/bytes/chars），
  `Result[Slice[T], AllocError]?` 会 push 2 个字（base/len）；`Err` 分支返回 Result 块指针（既有 ABI）。

### 2.3 容量

本次源码/数据布局随之调整（`names_stage.ls` 自身已到 330338 B，超过旧的 327680）：

- 源码上限 **327680 → 393216**；
- `membuf[1441792]` → **`membuf[1507328]`**：
  source `[0,393216)`、code `[393216,1441792)`、data `[1441792,1507328)`；
- helper flat binary **1085 → 1111 B**；生成器 `bootstrap/helper/embed_genop.py` 入库
  （`nasm -f bin` → 重写 `genop_str` 数组与拷贝循环），不再依赖本地 `.temp/` 脚本。

## 3. 测试

| 测试 | 期望 |
|---|---|
| `stage1_str_budget.ls` | 填满 arena 后 `str_try_concat` → `Err` 且 `arena_used()` 不变；`arena_reset()` 后 `Ok`；泛型 `+` 在满 arena 下得到空 `Str`（不 trap），reset 后恢复；退出码 7 |
| `slice_concat.ls` | `concat_into`/`append_into` 返回 `Result`，`match` 后 1+2+3+4+5=15 |
| `slice_concat_int.ls` | 同上（Slice[Int]），10+20+30+50=110 |
| `slice_concat_cap.ls` | 目标容量不足 → `Err`，`out` 未被部分写入，退出码 7（**旧行为是 exit 71**） |
| `arena_reset.ls` | 改用 `str_try_concat`；reset 前后两次拼接，退出码 2 |
| `reject/bls_str_plus.ls` | 直接 `Str + Str` → `E-LS-UNSUPPORTED` |

QEMU 全量：`PASS interpreted str budget -> ELF`、`PASS compiled str budget stage1 -> exit 7`、
`PASS compiled slice_concat -> exit 15`、`PASS compiled slice_concat_int -> exit 110`、
`PASS compiled slice_concat_cap -> exit 7`、`PASS compiled arena_reset -> exit 2`、
`PASS fixed point: stage2 == stage3`。

## 4. 行为/固定点

- **同源编译行为**：116 个输入里 113 个 `rc`/stdout/stderr 与 R4.3 前一致；3 个预期差异：
  `arena_reset.ls`（改用 `str_try_concat`，旧编译器不认识）、`stage1_str_budget.ls`（新内置）、
  `reject/bls_str_plus.ls`（旧编译器接受直接 `Str +`）。
- **所有生成 ELF 的字节都变化**：helper 被无条件嵌入每个程序，flat binary 1085 → 1111 B，
  代码地址/指令随之移动；因此不再以“逐字节一致”为回归信号，改由上面的行为对比 + QEMU 全量 CI 覆盖。
- `names_stage` 自编译：`9808e322…b666` 533184 B → **`4fa74081…9a0b` 552129 B**；
- QEMU 固定点 **`4fa74081…9a0b`**。

## 5. 边界

| 项 | 状态 |
|---|---|
| `Str +` / `concat_into` / `append_into` 预算不足 | ✅ 不动 `exit(70/71)`，失败可观察 |
| `str_try_concat`（Result） | ✅ |
| `concat_into`/`append_into`（Result） | ✅（签名变更：旧 `Slice[T]` → `Result[Slice[T], AllocError]`） |
| 泛型 `T + T` 的失败 | ⚠️ 不返回 `Result`（语法上仍是 `T`）：失败得到空 `Str`；需错误处理请用 `str_try_concat` |
| 直接 `Str/Slice +` | ✅ 现在稳定拒绝（旧实现是整数加法误编译） |
| 类型/tag 不匹配 | ⚠️ 仍 `exit(70)`（编译器不变量，正确程序不可达） |
| `Str` 分配的对齐 / 与 `Buffer` 的统一预算 | ✅ R4.2（`Str +` 也 8 字节对齐；共用 `current/end` 与计量槽） |
| `AllocError` 构造器/常量 | ❌ 仍是数值 `-1` |
| `Str +` 之外的分配（`slice`/`concat` 的 `Str +`） | ✅ 同一 helper |

`Result`（需要泛型返回类型的整体调整）、按 region 的硬配额、通用 free。
