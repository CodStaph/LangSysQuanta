# R4.2 / R4.4 · 真实 arena 计量 + region 预算视图

> 状态：**完成（2026-10-23）**。QEMU 固定点 `9d03f030…583b`，`stage2 == stage3`，`QEMU-GUEST: RESULT=PASS`。
> 上位：[`MEMORY.md`](../MEMORY.md) §R4、[`results/B3-arena.md`](B3-arena.md)、[`results/B3-buffer.md`](B3-buffer.md)。
> 范围：arena 的**计量与对齐收口**（R4.2）与**region 预算视图 + 动态容量**（R4.4）；
> 不做通用 `free`、非栈顶回收、按 region 的硬配额（region 共享同一 1 MiB 预算）。

## 1. R4.2 · arena 元数据、对齐与计量

### 1.1 数据结构

`heap_ptr_off` 从 3 个槽扩成 **7 个槽（56 B）**，全部在 data 段：

| 槽 | 含义 |
|---|---|
| `post[17010]` | `base` |
| `post[17011]` | `current` |
| `post[17012]` | `end`（`base + 1 MiB`） |
| `post[17018]` | `high_water`（历史峰值 `current-base`） |
| `post[17019]` | `allocs`（成功分配次数） |
| `post[17020]` | `rejects`（预算拒绝次数） |
| `post[17021]` | `reclaims`（回收次数） |

`base/current/end/high_water/allocs/rejects` 连续排列（`current=&base+8`、`end=&base+16`，因此
`high_water=&end+8`、`allocs=&end+16`、`rejects=&end+24`），`genop_str` 的 `Str +` 直接用
`[r8-8]`/`[r9+8..+24]` 访问，无需额外寄存器。

### 1.2 统一 8 字节对齐

- `arena_alloc` / Buffer 分配 helper 原本就向上对齐 8；
- 本次把 **`Str +` 也改成 8 字节对齐**（`genop_str.asm` 的 `concat`：`add size,7; and size,-8`），
  但 Str box 里记录的仍是**真实字节数**（`rbx`），不是对齐后的长度；
- 因而 `arena_used()` 现在等于“所有分配（含 Str 临时量）的对齐后总和”。

### 1.3 计量更新点

| 事件 | 更新 |
|---|---|
| `arena_alloc` 成功 / 失败 | `high_water=max(...)`、`allocs++` / `rejects++` |
| `Buffer.new` / `Buffer.try_new`（经 helper） | 同上 |
| `Str +`（flat helper） | 成功：`high_water`/`allocs`；失败：`rejects`（不推进 current） |
| `b.release()` / `drop` 成功 | `reclaims++` |
| `arena_reset()` | `reclaims++` |
| `region` 退出 | `reclaims++` |

`high_water` 是**程序生命周期内的峰值**，`arena_reset()`/回收不会降低它。

### 1.4 新内置 `arena_stat(sel)`

`sel` 只接受字面量 `0..3`（编译期常量）：

| `sel` | 值 |
|---|---|
| 0 | `high_water` |
| 1 | `allocs` |
| 2 | `rejects` |
| 3 | `reclaims` |

实现：`builtin_code` 18 → post kind 65（`emit_expr_c` 读对应槽并压栈）；selector 非法时
`arena_stat: selector must be 0..3`。

## 2. R4.4 · region 预算视图与动态容量

### 2.1 新内置 `region_used()`

`region_used() = current - mark`，其中 `mark` 是**最内层活跃 region 进入时的 `current`**；
没有活跃 region 时返回 `current - base`（即全局 `arena_used()`）。实现：`builtin_code` 19 →
post kind 66（读 `post[17013]` 的 `depth`，`depth>0` 时取 `mark[depth-1]`）。用于在嵌套
region 内观察“本 region 分配了多少”，region 退出的回退则把全局预算恢复。

### 2.2 动态容量

`Buffer.new[Int](cap, rgn)` / `Buffer.try_new[Int](cap, rgn)` 的 `cap` 本来就是运行时表达式；
本次用 `stage1_arena_region.ls` 固化：`let cap = 3; Buffer.new[Int](cap, heap)`、push 到满、
第 4 次 push 返回 `-1`，分配大小 `32 + cap*8 = 56`。

### 2.3 回收

- Buffer `release`/`drop`（LIFO，owner 匹配）→ `reclaims++`；
- region 退出自动回退 `current` → `reclaims++`；
- `arena_reset()` → `reclaims++`；
- `rejects` 只统计**arena 分配失败**（`Buffer.try_new`、`arena_alloc`、`Str +`），
  不统计 `concat_into` 的输出容量失败（那不是 arena 分配）。

## 3. 容量/布局修正（重要）

本轮扩容暴露并修复了一个**潜伏的布局 bug**：

- 数据重定位补丁表（`cs[3]`）原本放在 `post[60000..90000)`（每项 2 ints，容量 15000 项）；
- 编译 `names_stage.ls` 时重定位数已超过 **20000**，补丁表一路写进 `post[90000..]`（Option/Result 表）
  和 `post[100000..]`（表达式元数据），导致生成的 stage2 指令被写坏（`genop` 第一句
  `48 8B 05` 被改成 `48 0D …`），stage2 一启动就 SIGSEGV；
- 修复：**补丁表移到 `post[220000..287000)`（33500 项）**，`post` 219200 → **287000**；
- 为让 `seed --run`（宿主解释器 `data[]`）仍能运行编译器，同时缩小：
  - `membuf` 1507328 → **1245184**（source 393216 / code **786432** / data 65536）；
  - `out` 753664 → **610000**（最大输出 `names_stage`=575457，留 ~34 KB）；
  - 当前数组总量 ≈ **4.18 MB**；
- **宿主解释器上限 4 MiB → 16 MiB**（见 §3.1），因此上面的收缩只是为了省内存，不再是硬约束。
- 函数调用补丁表仍在 `post[40000..50000)`（调用数 ≤ 4000），变量表 50000 起（容量 4096）。

### 3.1 宿主解释器 4 MiB 上限（已解决）

`bootstrap/seed/seed.c` 里 `data[]` 同时服务两种模式：编译模式（目标程序的静态数据镜像）与
`--run` 模式（解释执行时程序的数组/变量/arena 内存）。原先 `DATA_MAX = 4 MiB`，两边都被卡住：
编译器自身数组已达 ~4.18 MB、`stage1` 再长大就无法本地解释运行。

修复：

- `DATA_MAX` **4 MiB → 16 MiB**（`data[]` 16 MB BSS；`--run` 的数组/变量/arena 上限随之提高）；
- `OUT_MAX` 与 `DATA_MAX` 解耦为 `CODE_MAX + DATA_MAX + 4096`（`out` 只用于编译模式），
  并在 `build_elf` 加 `if (total > OUT_MAX) die("output too large")`；
- 验证：`Array[U8, 8000000]` 的程序既能被 `seed --run` 解释执行（退出码 7），也能被 seed 编译成 8 MB ELF；
- seed 的**输出字节不变**（codegen 未改），因此 stage1-names/stage2/stage3 与固定点
  `9d03f030…583b` 完全一致；QEMU 全量 CI 仍 `QEMU-GUEST: RESULT=PASS`。

## 5. 行为/固定点

- 同源编译行为：118 个输入里 **116 个 `rc`/stdout/stderr 一致**，2 个预期差异是新测试
  （旧编译器不认识 `arena_stat`/`region_used`）；
- 生成 ELF 的字节全局变化（arena 结构 +32 B、helper 1085→1160 B、membuf/out/post 尺寸），
  回归信号仍以行为对比 + QEMU 全量 CI 为准；
- `names_stage` 自编译：`4fa74081…9a0b` 552129 B → **`9d03f030…583b` 575457 B**；
- QEMU 固定点 **`9d03f030…583b`**。
