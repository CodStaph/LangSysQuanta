# R4.7 · 句柄表压缩与 region 硬配额

> 状态：**完成（2026-10-24）**。QEMU 固定点 `96e6c63b…f82281`，`stage2 == stage3`，`QEMU-GUEST: RESULT=PASS`。
> 上位：[`MEMORY.md`](../MEMORY.md) §R4、[`results/R4.6-free.md`](R4.6-free.md)、
> [`results/R4.2-r4.4-arena.md`](R4.2-r4.4-arena.md)。
> 范围：① **Buffer 句柄表**（handle → block）与**移动式压缩**；② **`region r(cap) { ... }` 硬配额**。
> 仍然不做：非 Buffer 分配的移动（`Str`/裸 `arena_alloc` 块是 pinned）、并发、双空闲表。

## 1. 句柄表（handle → block）

### 1.1 为什么需要

R4.6 的空闲表只能复用空洞，**不能移动活对象**：`Buffer` 句柄与 `Str` box 里存的是 arena
偏移/指针，搬动数据会让它们失效。R4.7 给 `Buffer` 增加一层间接：

```text
handle table (data 段, post[17040] 指向):
  [0]              = slot count (<= 128, 只增不减)
  [8]              = live count (信息位)
  [16 + i*16]      = { off, size }      size == 0 表示槽空闲
```

- **Buffer handle = 槽下标**（不是偏移）；`-1` 仍是失败值；
- `Buffer` 变量、`Result.Ok` 载荷、`match` 绑定里保存的都是槽下标，搬动数据只改表项；
- 128 个槽，槽满时 `Buffer.new`/`try_new` 失败（`-1`/`Err(-1)`）。

实现仍在 [`bootstrap/helper/genop_str.asm`](../bootstrap/helper/genop_str.asm)：

| 入口 | ABI | 语义 |
|---|---|---|
| `buf_hreg` | `rdi=&ht, rsi=off, rdx=size` | 找一个 dead 槽（或追加），写入 `{off,size}`，返回 handle |
| `buf_hget` | `rdi=&ht, rsi=handle` | 返回 `off`，失效/越界返回 `-1` |
| `buf_hfree` | `rdi=&ht, rsi=handle` | 置 `size=0`，返回 `0`/`-1` |
| `buf_hpurge` | `rdi=&ht, rsi=limit` | 使 `off >= limit` 的表项失效 |
| `buf_hcompact` | `rdi=&free, rsi=&ht, rdx=&base, rcx=&current` | 移动活块，返回移动数 |

helper vector 扩为 **12 × int32（48 B）**，main 从 `genop_str[genop_bytes-48 ..]` 解码，
槽地址发布在 `post[17023..17034]`（旧 4 个入口的槽位不变）；handle 表在 BSS 中分配
（`16 + 128*16 = 2064 B`），只有源码出现 `region`/`Buffer`/`buffer_`/`arena_` 时才占空间。

### 1.2 所有 Buffer 操作都经过表

`Buffer.new`/`try_new` 分配成功后 `buf_hreg` 拿到槽下标；`len/cap/push/get/set/release/drop`
先 `buf_hget` 解析出当前 `off`。因此：

- 压实后旧 handle 继续可用；
- `release`/`drop` 成功时 `buf_hfree` 使槽失效——**重复释放现在返回 `-1`**（R4.6 会把重复项再插进空闲表）；
- `Buffer.try_new` 的 `Result.Ok` 载荷改为**真正的 handle**（此前实现固定写 0，只有第一个 Buffer
  恰好是 handle 0 时才正确；R4.7 顺带修复）。

### 1.3 移动式压缩（`arena_compact()`）

```ls
let moved = arena_compact();   // 返回移动的活块数，reclaims += moved
```

`buf_hcompact` 的算法（单线程、无递归）：

1. 按槽下标扫描活 Buffer；对每个块，在**空闲表**里找第一个满足
   `hole.size >= block.size` 且 `hole.off + block.size <= block.off` 的洞（只向下搬）；
2. `rep movsb` 搬 `size` 字节，更新表项 `off` 和 header 的 `data_off`；
3. 消耗洞（切分或删除），把旧位置通过 `buf_free` 插回空闲表（自动与相邻洞合并）；
4. 重复扫描直到一轮没有移动（每次移动 off 严格减小，必然终止）；
5. 最后丢弃**尾部**空洞并相应下调 `current`（尾部空洞可真正归还 arena）。

边界：

| 项 | 状态 |
|---|---|
| 移动 `Buffer` 块（句柄表间接） | ✅ |
| `Str` box / 裸 `arena_alloc` 块 | ❌ **pinned**（没有句柄，移动会破坏指针） |
| 合并/切分/回收尾部空洞 | ✅ |
| 空闲表满（64 项） | 压缩仍移动，但旧块可能无法入表（丢空间，不破坏正确性） |
| 重复释放检测 | ✅（handle 失效） |
| 压缩与 region | region 退出/`return`/`arena_rewind` 会用 `buf_hpurge` 清掉 mark 之上的 handle |
| 压缩跨 region mark | 若在 region 内显式压缩，region 活块可能被搬进 mark 之下的空洞；该块不会再被 region 退出回收（变量已出作用域，等价泄漏，`arena_reset` 才回收）。建议只在 root 或确认无跨 mark 空洞时压缩 |

## 2. region 硬配额

### 2.1 surface

```ls
region R(128) { ... }        // cap 是运行期 Int 表达式（常量/变量/四则/比较/括号）
region S { ... }             // 不带 cap：沿用原来的“只共享全局 arena”行为
```

`region_limit()`（新内置）返回**当前 region 的有效上限**：`end - 最内层 mark`；
无 region 时等于 `arena_budget()`。

### 2.2 实现：临时缩小 arena end

不需要改所有分配点：**region 进入时把 `[end]` 临时改成 `mark + cap`**，退出时恢复。

- 每个 region 帧新增 `lim[64]`（`post[17041]` 指向，512 B）保存进入前的 `end`；
- 进入：`lim[depth]=end; limit = clamp(mark+cap, mark, end); end=limit`；
  `cap` 为负时 clamp 到 `mark`（任何分配都失败），`cap` 超过父 region/全局剩余时取父上限；
- 退出 / `-> Int` 函数内 `return`：先恢复 `current=mark`、`end=lim[depth]`，再 purge 空闲表
  与 handle 表；
- 因此 `Buffer.new/try_new`、`arena_alloc`、`Str +`/`str_try_concat`、`concat_into`
  这些原本就检查 `[end]` 的路径**自动获得硬配额**，失败分别得到 `-1` / `Err(-1)`；
- 空洞复用不增加 `current`，所以不额外消耗配额（配额是 region 的 bump 上界）。

注意：`return` 的表达式现在**先求值、再 unwind region 帧**（R4.5 的实现是先 unwind 再求值，
导致 `return region_limit()` 读到恢复后的 root 值）；`-> Int` 的限制不变。

### 2.3 region 状态布局

```text
depth(8) | next(8) | mark[64](512) | seq[64](512) | lim[64](512) | handle table (2064)
```

仅 `region`/`Buffer`/`buffer_`/`arena_` 出现的程序分配这些 BSS 槽。

## 6. 边界

| 项 | 状态 |
|---|---|
| 句柄表容量 | 128 槽；槽满失败 |
| 移动对象 | 仅 `Buffer`（句柄表间接）；`Str`/裸块 pinned |
| 压缩触发 | 显式 `arena_compact()`；分配/释放不自动压缩 |
| 碎片 | 空闲表 + 合并 + 尾部回落；仍可能留下不可用的小洞 |
| 硬配额 | `region r(cap)`；`cap` 为运行期 Int；负 cap 视为 0 |
| 配额与空洞 | 复用已释放的空洞不增加 `current`，不计入 region 用量 |
| `region_limit()` | 有效 `end - mark`；无 region 时 = `arena_budget()` |
| 返回/跳出 | `break`/`continue` 跳出 region 仍拒绝；`-> Int` 内 `return` 会恢复 `end` |
| double-free | 现在通过 handle 失效检测（返回 `-1`） |
| 解释器/内存预算 | 宿主 `data[]` 16 MiB；`out` 900000；`MAX_SLICES` 1024 |

**后续建议**：R4 的两项遗留（句柄表压缩、region 硬配额）已收口。若要让 `Str` 也可移动，
需要把 `Str` box 也改为句柄间接（新的分配器设计），否则只能保持 pinned。
语言侧下一步：**B4 多参数泛型/约束**。
