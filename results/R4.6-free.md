# R4.6 · 通用 free、空洞复用与合并（碎片整理）

> 状态：**完成（2026-10-23）**。QEMU 固定点 `c8da4798…b2a2`，`stage2 == stage3`，`QEMU-GUEST: RESULT=PASS`。
> 上位：[`MEMORY.md`](../MEMORY.md) §R4、[`results/R4.2-r4.4-arena.md`](R4.2-r4.4-arena.md)、
> [`results/R4.4-r4.5-reclaim.md`](R4.4-r4.5-reclaim.md)。
> 范围：**任意顺序释放 + 空洞复用 + 相邻空闲块合并**；不做“移动活对象”的压缩（见 §5 边界）。

## 1. 设计

arena 仍然是一个 bump 区（`base/current/end` + R4.2 的计量槽），但新增一张 **空闲块表**：

```text
table:  [0]            = count
        [8 + i*16]     = { off, size }   按 off 升序，8 字节对齐
```

- 表本身在 data 段（`post[17022]` 指向它，容量 **64 项** = 1032 B）；
- 所有分配（`arena_alloc`、`Buffer.new`/`try_new`、`Str +` 之外）先尝试从表里 **first-fit** 取一块：
  找到 `size >= 请求` 的块；剩余 ≥ 8 字节时切分（表项 off 前移、size 减小），否则整块给出；
- 取不到才走原来的 bump 路径（并照常更新 `high_water/allocs`）；
- **释放**（任意顺序）把 `{off, size}` 按序插入表中并**合并相邻块**（前后各查一次），
  因此“碎片整理”在释放时就增量完成；另有显式 `arena_coalesce()` 做整表合并遍；
- `arena_used()` 仍是 **bump 上界**（`current-base`），释放不会降低它；空洞可被后续分配复用。

### 1.1 实现位置（`bootstrap/helper/genop_str.asm`）

为了避免在 stage1 源码里手写上百条 `emit1` 编码，空闲表算法用 **nasm** 实现在 flat binary 末尾：

| 入口 | ABI | 语义 |
|---|---|---|
| `buf_take` | `rdi=&table, rsi=size` | 返回 `off` 或 `-1`；可能切分 |
| `buf_free` | `rdi=&table, rsi=off, rdx=size` | 排序插入 + 双向合并；表满 `-1` |
| `buf_purge` | `rdi=&table, rsi=limit` | 丢弃 `off >= limit` 的项，截断跨越 limit 的项 |
| `buf_compact` | `rdi=&table` | 整表合并相邻项 |

- 生成代码通过 **`call qword [rip+slot]`** 调用：main 在 **emit_body 之前** 把 4 个入口的绝对地址
  写入 data 段的 4 个槽（`post[17023..17026]`），因为 emit 时记录的是 *槽的数据偏移*；
- 入口偏移由 flat binary 末尾的 **vector（4 × int32，绝对 blob 偏移）** 给出，main 从
  `genop_str[genop_bytes-16 ..]` 解码；`genop_bytes` 由 `bootstrap/helper/embed_genop.py` 自动维护。

### 1.2 surface

| 形式 | 语义 |
|---|---|
| `b.release()` / `drop b;` | **任意顺序**：栈顶 → 回退 `current`（与旧行为一致）；非栈顶 → 进空闲表（返回 `0`，不再是 `-1`） |
| `arena_free(off, size)` | 显式释放一个 `arena_alloc` 块（`size` 由调用方给出，需与分配时一致） |
| `arena_coalesce()` | 整表合并相邻空闲块（返回 `0`） |

- `release`/`drop` 仍要求 **owner 与当前 region 一致**（跨 region 仍 `-1`），但不再要求 LIFO；
- `arena_reset()` 清空空闲表（count=0）；`arena_rewind(m)` 与 **region 退出** 调用 `buf_purge`，
  丢弃 mark 之上的空洞（跨越 mark 的空洞被截断）；
- 回收计数：非栈顶 `release`/`drop`、`arena_free` 成功、`arena_rewind`、`arena_reset`、region 退出都计入
  `reclaims`。

## 2. 本次一并修复的容量/布局问题

source 增长到 ~384 KB、编译器自身语句/重定位数量继续增长，暴露了 3 个布局问题：

| 问题 | 修复 |
|---|---|
| 数据重定位补丁表在 `post[220000..]`，与 `sast`（已长到 233023）**重叠** → sast 被写坏（`slice: bad value`、stage2 崩溃） | 补丁表移到 **`post[240000..320000)`**（40000 项），`post` 287000 → **320000** |

## 3. 测试

新增 `stage1_arena_free.ls`（退出码 7）：

1. 三个 Buffer（0/48/96）→ `b.release()`（非栈顶）返回 0，`arena_used()` 不变；
2. 再 `Buffer.new(2)` **复用 b 的空洞**（used 仍 144）；
3. 释放后 a（0..48）与 d（48..96）合并成 96 B 空洞 → `Buffer.new(6)`（需 80 B）**只有合并后才能成功**；
4. 顶层 Buffer `release` 仍走回退（used 降到 96）；
5. `arena_rewind(0)` 丢弃空洞；重新分配后 used 恢复；
6. `arena_alloc(16)` → `arena_free(p,16)` → `arena_alloc(16)` 复用同一偏移；`arena_coalesce()` 返回 0；
7. `arena_stat(3)`（reclaims）精确为 7。

`stage1_buffer_release.ls` 更新：非栈顶 `release` 的期望从 `-1` 改为 `0`（新语义），其余不变。

## 5. 边界

| 项 | 状态 |
|---|---|
| 任意顺序释放（Buffer `release`/`drop`、`arena_free`） | ✅ |
| 空洞复用（first-fit + 切分） | ✅ |
| 相邻空闲块合并（free 时增量 + `arena_coalesce()`） | ✅ |
| `arena_used()` 语义 | bump 上界（释放不降低；空洞复用不增长） |
| 空闲表容量 | **64 项**（表满时 `release`/`arena_free` 返回 `-1`） |
| 移动活对象的压缩/整理（compaction） | ❌ 会破坏 Buffer 句柄与 Str 指针；需要句柄表/间接层 |
| 重复释放（double free）检测 | ❌ 调用方负责；重复 free 会插入重复表项 |
| `Str +` 临时块的显式释放 | ❌ 尺寸含对齐填充、调用方不可知；用 `mark/rewind`/`reset` |
| 按 region 的硬配额 | ❌ 仍无 surface 语法 |
| 解释器/内存预算 | 宿主 `data[]` 16 MiB；当前数组总量 ≈ 4.85 MB |

**后续建议**：R4 的“通用 free + 空洞复用 + 合并”已收口。若还要做真正的压缩，需要引入
**句柄表（handle → block）**并让 `Str` 也走间接引用（属于新的分配器设计，建议单独立项）。
语言侧下一项：**B4 多参数泛型/约束**。
