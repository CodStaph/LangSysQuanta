## 1. 交付范围

B0.3c 把 `emit_body` 的「边扫源码边发射」拆成：

| pass | 作用 | 产生代码 |
|---|---|---|
| `scan_stmts` | 在 `check_calls` 之后，对每个函数体建语句 AST（`sast`） | 否 |
| `emit_stmt_list` | 用显式 frame stack 按 AST 发射；`if/while/break/continue` 用 AST 标签 | 是 |
| `emit_stmt_span` | 叶子语句/`match` 的旧单遍解析+发射（按 AST span 截取） | 是 |

- **无递归**：编译产物函数使用全局局部槽，AST 遍历和块扫描都用显式数组栈。
- `if/while` 不再依赖 `ck/cje/cstart/cjmp/bloop/bpos` 的深度巧合；标签与回填由 frame 显式驱动。
- `break/continue` 使用显式的循环深度/起点标签；`break` 仍按层回填。
- `region` 作为词法块展开；`comptime` 空块 no-op，非空块保持
  `E-LS-UNSUPPORTED`（`bls_comptime` 负例通过）。
- `match` 仍是叶子：沿用旧 match 解析器（arm 目前只支持 `return expr;`）。

**边界（明确未做）**：表达式的后缀 IR 仍由叶子/条件在发射时解析；B0.3c 完成的是
**语句级 AST + 控制流**，不是完整的表达式 AST/两阶段表达式发射。表达式相位前移
（`expr_start/expr_len` + phase A 建 IR）留作后续增量。

## 2. `sast` 布局

`post` 扩到 201000 ints：

```text
post[140000..141023]  fd（函数表，1024 ints）
post[141024..198951]  sast（语句 AST，57928 ints）
post[198952..200999]  ctxi（Int 状态，2048 ints）
```

`sast[0]` = 记录数；每条记录 6 ints：

```text
+0 kind  +1 start  +2 end
+3 first_child  +4 next_sibling  +5 last_child
```

kind：`0 block, 1 if, 2 while, 3 region, 4 comptime, 5 break, 6 continue, 7 leaf/match`。
`scan_add_node` 用父节点的 `last_child` 做 O(1) 追加；记录从 `sast[257]` 开始，
容量约 **9500** 条（超过返回 `stmts: too many statements`）。

每个函数在 `sast[1 + fi*2]` 存根 block 下标；`fi` 与 `fd` 的顺序一致。

## 3. 发射算法

### `if`

```text
cond; jz else; then; jmp end; else:; else-body; end:
```

`else if` 是嵌套 `K_IF` 子节点；frame phase 负责在 then 结束后发 `jmp end` 并回填
`jz`，在 else 结束后回填 `jmp end`。

### `while`

```text
loop_start: cond; jz end; body; jmp loop_start; end:
```

进入时把 `loop_start` 存进 `cstart[cd]`，`cd` 为 AST 循环深度；`continue` 直接
`jmp cstart[cd-1]`，`break` 记录 `bpos/bloop`，循环退出时按层回填到 `end`。

### 叶子 / match / region / comptime

- 叶子与 `match`：`ctxi[SPAN_START/SPAN_END]` 取 AST span，调用 `emit_stmt_span`；
  该函数仍是旧的单遍解析器，负责 `let/assign/return/write/expr/match`。
- `region`：AST 子 block 展开（词法分组）；B2-1 已在 AST frame 中恢复
  「活跃 region 重名」检查（`rname`/`rlen`/`RDEPTH`，逐字节比较，不插入 name table）。
- `comptime`：空 block 直接跳过；非空 block 报
  `stage1: E-LS-UNSUPPORTED: comptime blocks with non-empty bodies are not implemented in B-LS yet`。

### 无递归

`emit_stmt_list` 使用 `fnodes/fphase/fd1/fd2/fchild`（各 256 ints）作为显式 frame stack；
`scan_stmts` 使用 `bs/be/bp`（各 256）作为 block 任务栈。没有递归调用，因此 stage1
自举时不受「编译产物函数使用全局局部槽」限制。

## 4. 数据布局 / 源码上限

为了同时容纳源码、AST 和 `ctxi`，本轮重新平衡：

```text
membuf: source [0, 294912)  code [294912, 1343488)  data [1343488, 1409024)
post:   201000 ints
```

- 源码上限从 **262144** 提到 **294912**（`read_file` cap 与 `source too large` 检查同步）；
  否则新增 AST 代码会让 `names_stage.ls` 自身超过旧上限，自编译被截断。
- `scan_funcs` 的 body-span 修复：返回类型可能是 `Option[U8]`/`Result[T,E]`/`Slice[...]`，
  现在从参数 `)` 之后用 `scan_until_lbrace`/`scan_block_end` 找函数体 `{`，不再只扫
  返回类型标识符。
- `emit_body`、`emit_stmt_list`、`emit_stmt_span` 的参数都保持 5 个槽
  （`mem` 2 + `ps` 2 + `n` 1）。
